# 세션 요약: 프로젝트 초기화 및 설계 (2026-05-07)

## 세션 목표

Synology NAS용 Docker 기반 사진 앨범 & 슬라이드쇼 웹 앱의 초기 설계 문서 작성 및 프로젝트 초기화.

---

## 수행 내용

### 1. 요구사항 정의 및 계획 문서 작성 (`doc/plan.md`)

사용자가 제시한 8가지 기능 요구사항을 FR/NFR 형태로 구조화:

- **FR-01 (Admin 전용)**: NAS 사진 폴더 탐색 및 검색(이름/날짜/폴더/파일명), 앨범 생성·편집·삭제, 사진 추가/제외(파일 삭제 아님), 공유 링크 생성 및 패스워드·만료일 설정
- **FR-02 (공유 링크 뷰어)**: 패스워드 입력 화면, 만료 링크 차단, 앨범 메인 화면(이름/이미지 수/생성일/만료일), 슬라이드쇼 시작·설정 버튼, 전체 ZIP 다운로드 버튼
- **FR-03 (슬라이드쇼)**: 자동 전환, 랜덤 전환 효과, Ken Burns 효과, 키보드/버튼 네비게이션, 수동 이동 시 동일 전환 효과, 개별 이미지 다운로드, 일시정지/재개
- **FR-04 (배경음악)**: NAS 오디오 지정, ON/OFF, loop 재생, 음량 조절

비기능 요구사항: Docker 단일 컨테이너, NAS 원본 읽기 전용 마운트, 데이터 외부 볼륨 영속, 모바일 터치 지원, 썸네일 캐시.

기술 스택 확정:
| 영역 | 선택 |
|------|------|
| Backend | Python / FastAPI |
| Frontend | Vanilla JS + HTML/CSS |
| DB | SQLite |
| 이미지 처리 | Pillow (PIL) |
| 컨테이너 | Docker + docker-compose |

5단계 개발 마일스톤 정의 (Phase 1 Core Backend → Phase 5 Docker 패키징).

### 2. 상세 설계 문서 작성 (`doc/design.md`)

- **시스템 아키텍처**: NAS 내 단일 Docker 컨테이너, FastAPI가 정적 파일 + REST API + 미디어 서빙을 모두 담당
- **데이터 모델**: ERD 및 SQLite DDL (albums, album_photos, share_links, thumbnail_cache)
- **REST API 전체 목록**: 인증(/api/auth/*), Admin 파일 탐색/앨범/링크 관리(/api/admin/*), 공유 뷰어(/api/share/{token}/*), 미디어 서빙(/thumb, /media, /music)
- **화면 와이어프레임**: 앨범 메인, 슬라이드쇼 설정 패널, 슬라이드쇼 화면
- **슬라이드쇼 엔진**: 9가지 전환 효과 목록, Ken Burns 8방향 CSS keyframes + 동적 클래스 부착, IDLE→PLAYING→TRANSITION 상태 머신, N+1/N+2 프리로드 전략
- **썸네일 정책**: small(300×200) / medium(800×600), on-demand 생성, MD5 파일명, EXIF orientation 보정
- **보안 설계**: Admin JWT(HS256, 8h) + 공유 링크 httpOnly 세션 쿠키(24h) 이중 인증
- **Docker 구성**: Dockerfile, docker-compose.yml 템플릿
- **Frontend 모듈 구조**: router.js, api.js, auth.js, TransitionEngine, KenBurns, Preloader, MusicPlayer 클래스 인터페이스
